## 2026-10-12 書き出しの高速化と共有画像の修正

- 合成処理を 4 本に並列化し、映像・音声を元の順序に集約する。待機は最大 8 イベント。ネイティブ形式のソフトウェアデコードは 2 スレッド、FFV1 は 8 スレッド・16 スライス。H.264 は VideoToolbox を優先し、初期化失敗時はソフトウェア圧縮へ切り替える。非対応音声は映像コピーと AAC 変換で処理し、映像のエンコードは一度だけにする。
- 旧実装でデコードした HEVC の共有画像への直接書き込みが後続フレームに影響する問題を確認。合成前の `make_writable()` で共有画像を保護する。独立した読み取りで得た元動画に同じ雲を重ねる期待値と、実 HLG 69 フレームの MKV 出力の全 YUV サンプルが完全一致。
- PNG の前処理と合成係数は各処理が独立して再利用。LRU キャッシュは各 64 MB 以下。旧レンダラの出力ハッシュに対し、6 ピクセル形式、両レンジ、SDR/HLG、3 色行列、端の切り取り、移動、重なりで全サンプルが一致。alpha がゼロのサンプル保持、キャッシュ破棄後の一致も確認。
- 合成単体の計測は **M5 Pro / 48GB**、3840×2160 / HLG / YUV420 10bit、24 顔 × 30 フレーム、位置と 2 サイズを切替、3 回中央値。既定 512px PNG は旧 5.5487 秒 → 0.2733 秒（約 20.3 倍）、debug 1254px PNG は旧 17.3820 秒 → 0.2700 秒（約 64.4 倍）。両方の全 YUV サンプルが一致し、キャッシュ約 9.3 MB。合成単体の数字であり、書き出し全体の倍率ではない。M1 Max そのものの実測でもない。
- 書き出し全体も **M5 Pro / 48GB** で旧 `87bfdb8` と比較。既定 512px PNG・固定 3 箇所の雲を使用し、3 回中央値。提供動画の 4K HLG / AAC 69 フレームは MP4 **4.4720 → 2.2959 秒（約 1.95 倍）**、MKV **5.5429 → 3.5961 秒（約 1.54 倍）**。1080p / 30fps / 90 フレームの合成映像では、AAC 入力の MP4 は **1.8957 → 0.6472 秒（約 2.93 倍）**、MKV は **1.6116 → 0.4530 秒（約 3.56 倍）**。PCM 音声入力の MP4 は **2.3059 → 0.6499 秒（約 3.55 倍）**、MKV は **1.5519 → 0.3893 秒（約 3.99 倍）**。実動画の全編・実検出した全顔の書き出し計測ではない。
- 上記の HLG MP4 は旧ビットレート設定を維持。SDR MP4 は CRF 16 のソフトウェア H.264 から高ビットレートのハードウェア H.264 に変わるため、同じ画質・容量での速度比較ではない。MP4 は引き続き非可逆。初回の別測定とは負荷などが異なるため、ここでは連続した最終比較の中央値を記載。

## 2026-10-12 雲の細かな揺れを抑制

- 提供動画の冒頭 69 フレーム、1,013 顔矩形で包含と人物情報の保持を確認。対応した 988 組のうち、元の中心移動が 8px 以下の 115 組では平均移動量 **3.79 → 2.06px（45.5% 減）**。安定化の追加処理は **0.015 秒**（包含等の検証を含む一例）。実測機は M5 Pro / 48GB。実際の大きな動きを含む全体の加速度変動の改善は確認できていないため、動画全体の見た目の滑らかさを保証する値ではない。
- 実際の雲の配置処理に、50px の静止顔に ±2px の検出揺れを与える試験では、雲の位置・寸法の総変動が 90% 以上減少し、開始 8 フレーム以降は一定。大移動、縮小、複数顔の一対一対応、カット・欠落・時間間隔でのリセット、可変フレームレート、表示許可の保持を含む新規テスト 14 件成功。
